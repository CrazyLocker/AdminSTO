# AdminSTO v1.2.0 — система управления автосервисом

> **Назначение:** точка входа в проект: описание возможностей, сборка и запуск,
> карта документации.
> **Актуализировано:** 18.11.2026
> **Версия ПО:** 1.2.0

## 📦 Описание

AdminSTO — настольное приложение для автоматизации работы небольшого
автосервиса на JavaFX: клиенты и их автомобили, заказы-наряды, справочники
услуг и запчастей, склад, календарь записей, система лояльности и отчётность.
Данные хранятся локально в SQLite, сетевого доступа нет.

## ✨ Возможности

- **Клиенты и автомобили** — карточка клиента, несколько автомобилей, пробег,
  дата последнего ремонта; поиск по телефону в человеческом формате (`+7 900 111-00-02`).
- **Заказы-наряды** — услуги и запчасти, количества, скидки по лояльности,
  статусы «Новый», «В работе», «Закрыт», списание и возврат остатков.
- **Календарь «Запись»** — недельный и месячный режимы, карточки записей
  (клиент, автомобиль, услуга, мастер), цветная полоса статуса связанного
  заказа, легенда статусов и счётчики записей в заголовках дней.
- **Справочники** — услуги (обычные, ТО, тюнинг) и запчасти с категориями,
  ценами, остатками, минимальным запасом и связями «услуга → запчасть».
- **Склад** — приход и списание запчастей.
- **Система лояльности** — звёзды ТО (до 5) и Stage 1–3 тюнинга; скидки
  5/10/15 % применяются к строкам заказа по категории.
- **Оформление** — 7 тем AtlantaFX (Primer Light/Dark, Nord Light/Dark,
  Cupertino Light/Dark, Dracula), вкладка «Внешний вид» в настройках.
- **Таблицы** — чередование строк («зебра»), голубая подсветка выбранной
  строки; ширина, порядок и сортировка колонок сохраняются между запусками.
- **Отчёты и PDF** — сводный отчёт по заказам, печать заказа-наряда в PDF.
- **Резервное копирование** — автоматические и ручные ZIP-бэкапы БД и
  состояний интерфейса, восстановление с проверкой архива.
- **Импорт/экспорт** — XML/CSV/JSON для клиентов, услуг и запчастей.

## 🔧 Системные требования

| Режим | Требования |
|---|---|
| Сборка из исходников | JDK 21, Gradle Wrapper 8.5, ~1 ГБ на диске, интернет для зависимостей |
| Запуск готового JAR | JRE 21, ~100 МБ на диске |
| Портативная сборка | Windows 10/11; JRE не нужен — встроен в app-image |

Поддерживаемые ОС: Windows 10/11, Linux, macOS. Портативный релиз собирается
workflow на `windows-latest`.

## 🚀 Быстрый старт

### Запуск из исходников

```bash
./gradlew run                 # запуск приложения
./gradlew build               # сборка + юнит-тесты + пороги покрытия
./gradlew uiTest              # JavaFX UI-тесты (headless)
```

### Портативная сборка (jpackage)

```bash
./gradlew jpackage
```

Результат — app-image `build/jpackage/AdminSTO` с исполняемым файлом и
встроенным JRE. В Windows-релизе эта папка упаковывается в
`AdminSTO-Windows.zip`.

### Релиз по тегу

Workflow `.github/workflows/release.yml` запускается при пуше тега `v*`:
собирает проект, выполняет `jpackage`, упаковывает `build/jpackage/AdminSTO`
в `AdminSTO-Windows.zip`, загружает артефакт и создаёт GitHub Release.

```bash
git tag v1.2.0
git push origin v1.2.0
```

### Демонстрационные данные

```bash
# Клиенты, заказы и уровни лояльности
python tools/seed_test_data.py --db T:/AdminSTO/autoservice.db --apply

# Записи календаря (клиенты и услуги уже должны быть в базе)
python tools/seed_appointments.py --db T:/AdminSTO/autoservice.db --replace
```

Подробности и флаги — в [описании инструментов](docs/SEED_TEST_DATA.md).

## ⚙️ Конфигурация

| Параметр | Значение по умолчанию | Где задаётся |
|---|---|---|
| Файл БД | `autoservice.db` в рабочей директории | `DatabaseFactory` |
| Тема | `primer-light` | `config/theme.txt` |
| Состояние окон | `config/window-state/*.json` | `WindowStateManager` |
| Состояние таблиц | `config/table-state/*.json` | `TableStateManager` |
| Логи | `logs/autoservice*.log` | `logback.xml` |

Смена темы сохраняется сразу, но применяется при следующем запуске: динамическая
подмена набора стилей в JavaFX 21 не поддерживается.

## 📤 Экспорт данных

- **Заказ-наряд в PDF** — контекстное меню заказа → «Сохранить заказ-наряд в PDF».
- **Справочники** — «Файл» → «Экспорт» / вкладка «Импорт/Экспорт» в настройках:
  клиенты, услуги, запчасти в CSV, XML или JSON.
- **Общий отчёт** — кнопка «Отчёт» на дашборде: заказы, выручка, статусы, топ услуг и запчастей.

## 🔧 Резервные копии

- Автоматические бэкапы по расписанию из настроек, ручной запуск — там же.
- Формат: ZIP с базой `autoservice.db` и файлами `config/table-state`,
  `config/window-state`.
- Хранится до 14 последних копий (настраивается).
- Восстановление проверяет архив до замены БД и закрывает пул соединений.

## 📊 Логирование

`logs/autoservice.log` — текущий лог, `logs/autoservice.yyyy-MM-dd.log` —
архив с ротацией 30 дней и ограничением 100 МБ. Портативная версия пишет
логи в `logs/` рядом с исполняемым файлом.

## 📋 Известные ограничения

1. Нет аутентификации и ролей — приложение рассчитано на доверенное рабочее место.
2. Портативный релиз собирается только для Windows.
3. Покрытие `views`/`dialogs` низкое в задаче `test`: интерфейс проверяется
   отдельными UI-тестами.
4. Часть крупных экранов (`SettingsView`, `AppointmentView`, `DashboardView`)
   остаётся большими классами — см. [CODE_REVIEW.md](docs/CODE_REVIEW.md).
