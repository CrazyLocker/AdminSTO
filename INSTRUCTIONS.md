# Руководство пользователя AdminSTO 1.2.0

> **Назначение:** инструкция для администратора и мастера-приёмщика: запуск,
> экраны, календарь записей, настройки и обслуживание данных.
> **Актуализировано:** 18.11.2026
> **Версия ПО:** 1.2.0

## 1. Запуск

| Способ | Действие |
|---|---|
| Из исходников | `./gradlew run` (нужен JDK 21) |
| Готовый портативный пакет | Распаковать `AdminSTO-Windows.zip` и запустить `AdminSTO.exe` |
| JAR из сборки | `java -jar build/libs/autoservice-admin.jar` |

При первом запуске рядом создаются `autoservice.db`, каталоги `config/`,
`logs/`, `backups/`. База и настройки локальные: приложение не обращается к сети.

Если сохранённый размер окна больше текущего экрана (сменили монитор или
масштаб), `WindowStateManager` уменьшает окно до границ экрана. Позиция и
размер окна сохраняются при закрытии.

## 2. Главное окно

Сверху — восемь вкладок:

| Вкладка | Для чего |
|---|---|
| **Дашборд** | Сводка: активные заказы, записи на неделю, выручка, быстрые действия и кнопка «Отчёт» |
| **Клиенты** | База клиентов, поиск, карточка клиента и его автомобилей |
| **Заказы** | Заказы-наряды, фильтры, статусы, PDF, детали заказа |
| **Услуги** | Справочник услуг: цены, категория, длительность |
| **Запчасти** | Справочник запчастей: цены, остаток, минимальный запас, связи с услугами |
| **Склад** | Приход и списание запчастей |
| **Запись** | Календарь записей: неделя/месяц |
| **Настройки** | Внешний вид, параметры приложения, лояльность, связи, ТО, бэкапы, импорт/экспорт |

Таблицы поддерживают сортировку по клику на заголовок. Ширина, порядок и
сортировка колонок сохраняются при закрытии и восстанавливаются при следующем
запуске (`config/table-state/*.json`). Нечётные строки залиты «зеброй», выбранная
строка подсвечена голубым.

## 3. Клиенты и автомобили

- **Новый клиент** — кнопка «Новый клиент»: имя, фамилия, телефон, автомобиль,
  госномер. Телефон вводится цифрами после `+7`, отображается как
  `+7 (900) 123-45-67`.
- Карточка клиента показывает контакт, автомобили, пробег, дату последнего ремонта,
  звёзды ТО и статус тюнинга.
- У клиента может быть несколько автомобилей (`client_cars`).
- Удаление клиента подтверждается; связанные заказы и записи обрабатываются
  по правилам внешних ключей.

## 4. Заказы-наряды

1. Вкладка **Заказы** → «Создать заказ» (или кнопка на дашборде).
2. Выберите клиента и автомобиль, добавьте услуги и запчасти.
3. В таблицах строк показываются цена, количество, скидка % и сумма с учётом
   скидки. Скидка определяется категорией строки (ТО/тюнинг/обычная).
4. Сохраните заказ. Остатки запчастей списываются; при отмене редактирования —
   возвращаются.

Статусы заказа: **Новый**, **В работе**, **Закрыт**. При закрытии заказа
начисляются звёзды ТО и сумма тюнинга, если выполнены правила лояльности
(см. [LOYALTY_SYSTEM.md](docs/LOYALTY_SYSTEM.md)).

Действия: «Изменить», «Удалить» (с подтверждением), «Детали», «Сохранить
заказ-наряд в PDF». Закрытый заказ редактировать нельзя.

## 5. Календарь «Запись»

- Переключатель **Неделя / Месяц** в верхней панели.
- Навигация: `◀` / `▶` и кнопка «Сегодня»; дата выбирается в календаре.
- В недельном режиме каждая запись — карточка: клиент, автомобиль, услуга,
  мастер; слева цветная полоса статуса связанного заказа. В заголовке дня —
  число и счётчик записей.
- В месячном режиме — строки записей с точкой статуса и временем, у дней с
  переполнением показывается «+N».
- Легенда под календарём: «Запланировано», «В работе», «Закрыт», «Без заказа».
- Двойной клик по свободной ячейке создаёт запись на это время.
- Время — слоты 08:00–20:00, мастера — из `AppConstants.MASTERS`.

Статусы записи: **Новая**, **Подтверждена**, **Выполнено**, **Отменена**.
Создание, изменение и удаление записи подтверждаются.

## 6. Справочники и склад

- **Услуги**: название, цена, длительность, категория (`REGULAR`,
  `MAINTENANCE`, `TUNING`), при необходимости — объём масла и автоматически
  добавляемая запчасть.
- **Запчасти**: название, артикул, производитель, совместимые модели, цены
  закупки и розничная, остаток, минимальный запас, место хранения, единица
  измерения (`шт`, `л`, `компл`).
- **Склад**: «Внести приход» и «Списание» меняют остаток; низкий остаток
  подсвечивается.

## 7. Настройки

Вкладка **Настройки** содержит восемь разделов:

| Раздел | Что настраивается |
|---|---|
| **Внешний вид** | Тема оформления: Primer Light/Dark, Nord Light/Dark, Cupertino Light/Dark, Dracula. Выбор сохраняется в `config/theme.txt` и применяется после перезапуска |
| **Настройки приложения** | Параметры в таблице «ключ — значение — описание» |
| **Автозаполнение** | Правила автоматического добавления запчастей к услугам |
| **Лояльность** | Интервалы ТО, максимум звёзд, скидки 3/4/5 звёзд, пороги и скидки Stage 1–3 |
| **Связи** | Дерево «услуга → запчасти»: добавить, изменить, удалить связь |
| **Расходники ТО** | Набор запчастей по модели автомобиля (13 моделей GWM + ручной ввод) |
| **Резервное копирование** | Автобэкап, время, количество копий, ручное создание и восстановление |
| **Импорт/Экспорт** | Импорт клиентов, услуг, запчастей из XML; экспорт в CSV/XML/JSON |

## 8. Резервное копирование и восстановление

- Бэкап — ZIP с текущей БД и файлами `config/table-state`, `config/window-state`.
- Перед восстановлением архив проверяется; пул соединений закрывается,
  файл БД заменяется атомарно, затем БД переинициализируется. При ошибке
  выполняется откат из копии, созданной перед заменой.
- Старые копии удаляются по настройке «количество хранимых бэкапов».

## 9. Импорт и экспорт

- Импорт клиентов, услуг и запчастей — XML. Дубли клиентов проверяются по
  телефону, услуг — по названию, запчастей — по артикулу.
- Экспорт — CSV, XML, JSON для клиентов, услуг и запчастей.
- Заказы, записи и связи услуг с запчастями при импорте не переносятся.
- Демонстрационные данные удобнее заливать скриптами из
  [SEED_TEST_DATA.md](docs/SEED_TEST_DATA.md).

## 10. Отчёты

Кнопка **«Отчёт»** на дашборде открывает сводку: количество заказов и
клиентов, выручка, распределение по статусам, топ услуг и запчастей.
PDF-экспорт заказа-наряда выполняется из контекстного меню заказа;
сводный отчёт открывается в отдельном окне.

## 11. Завершение работы

При закрытии окна сохраняются состояние окна, всех таблиц и данные из кэша.
Дождитесь завершения записи; принудительное завершение процесса может
оставить незаписанные изменения. Для ручной страховки используйте
«Создать резервную копию сейчас».

## 12. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Приложение не запускается | Установлен JDK/JRE 21; для портативной версии — запущен `AdminSTO.exe`, а не JAR |
| Тема не изменилась | Перезапустите приложение: тема применяется только при старте |
| Не видно записей в календаре | Выбран другой период; записи создаются на вкладке «Запись» |
| Не сохраняются ширина/сортировка таблиц | Каталог `config/table-state` должен быть доступен на запись |
| Ошибка восстановления из бэкапа | Архив повреждён или не содержит `autoservice.db`; приложение отменит восстановление и оставит текущую БД |

Технические подробности и известные ограничения — в
[README.md](README.md) и [TECHNICAL_SPECIFICATION.md](docs/TECHNICAL_SPECIFICATION.md).
